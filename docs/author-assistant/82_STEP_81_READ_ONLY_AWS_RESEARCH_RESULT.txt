3. STEP 81 FLOW

1. Create or resume an Author Assistant session.
2. Choose whether to start read-only research.
3. Stop safely if the AI key is unavailable.
4. Search only official AWS documentation when the key is available.
5. Save the proposed research to the same session.
6. Display each proposed source separately.
7. Ask whether to keep each source.
8. Save accepted and rejected source decisions separately.
9. Make no Author draft changes.

4. OFFICIAL AWS DOMAIN CONTROL

The API request allows exactly:

docs.aws.amazon.com

A proposed URL is rejected unless:

1. It uses HTTPS.
2. It is under docs.aws.amazon.com.
3. It was returned by the protected API web search.
4. It is not a duplicate.

5. REQUIRED SOURCE COVERAGE

The research must include:

1. An AWS service guide for Console instructions.
2. The AWS CLI Command Reference for commands and parameters.
3. The AWS Service Authorization Reference for IAM permissions.

Missing coverage stops the result from being accepted as complete.

6. AI KEY SAFETY

The script reads OPENAI_API_KEY only from the local process environment.

The key is:

1. Not placed in the browser app.
2. Not placed in a VITE variable.
3. Not written into the request body.
4. Not written into session files.
5. Used only in the private Authorization header.

The API request also sets storage to false.

7. SAVED FILES

Before research:

research-request.json

After protected research:

All files remain inside the same Author Assistant session folder.

8. RESUME SAFETY

If research completed but source review was interrupted, the next run resumes the saved source review.

It does not repeat the AI request.
It does not create a duplicate session.

If accepted sources already exist, the script reports that they are complete and does not repeat research.
