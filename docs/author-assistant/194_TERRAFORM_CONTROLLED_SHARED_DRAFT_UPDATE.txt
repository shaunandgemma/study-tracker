194. TERRAFORM CONTROLLED SHARED DRAFT UPDATE

1. Purpose
Update the one existing Terraform Associate Beginner Shared Draft from the exact verified 102-checkbox Local Draft without creating a duplicate Shared Draft.

2. Matching rule
The Author page matches the Local and Shared Drafts by the exact programme ID. The update is available only when exactly one Shared Draft matches, both drafts belong to the signed-in Author, and the Local Draft is a verified Author Assistant handoff.

3. Preview
The Shared-storage panel displays both draft IDs, the Local revision, the Shared revision, the content fingerprints, and the exact next Shared revision before enabling the action.

4. Confirmation
The Author must confirm the exact Local Draft ID and existing Shared Draft ID. A normal copy is not offered when an existing Shared Draft already represents the programme.

5. Conflict protection
The action stops if either draft revision or fingerprint changes, ownership changes, more than one Shared Draft matches, or an active release candidate exists for the current Shared revision.

6. Saved result
The existing Shared Draft ID is preserved. Its editable content is replaced by the verified Local content and its revision advances by exactly one. The Local Draft remains unchanged.

7. Boundaries
No Local Draft is deleted. No second Shared Draft is created. No release candidate is created, approved, rejected, or published. No AWS operation is performed.

8. Verification
Forty-two focused Author storage, handoff, and Shared update tests passed. The production build passed. Lint reported only existing unrelated warnings.
