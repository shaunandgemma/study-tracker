160. AUTHOR ASSISTANT - NEW OR UPDATE EXISTING FOLLOW ALONG

1. PURPOSE

The Author Assistant can now do either of these:

1. New Follow Along
2. Update Existing Follow Along


2. RUN THE SCRIPT

Open PowerShell in:

E:\code\study-tracker

Run:

npm run author-assistant:secure


3. CREATE A NEW FOLLOW ALONG

1. Select 1 - New Follow Along.
2. Enter the AWS service details.
3. Review the complete Console and CLI preview.
4. Accept the preview.
5. Open the signed-in Author page.
6. Select Local Drafts.
7. Upload the two saved JSON files.
8. Validate the read-only preview.
9. Choose Create One Private Author Draft.
10. Copy the Local Draft to Shared Drafts when ready.


4. UPDATE AN EXISTING FOLLOW ALONG

1. Select 2 - Update Existing Follow Along.
2. The script reads the controlled published Follow Along list.
3. It displays the exact available programme names and revisions.
4. Select the required Follow Along by number.
5. Describe exactly what should change.
6. Confirm or change the learner level and Region.
7. Review the complete replacement preview.
8. Accept the preview.
9. Open the signed-in Author page.
10. Select Shared Drafts before uploading the files.
11. Upload the package and acceptance JSON files.
12. Select Validate Read-Only Preview.
13. Review the exact revision comparison.
14. Tick the confirmation box.
15. Select Update This Existing Follow Along.

The existing Shared Draft moves forward by exactly one revision.
No new draft is created.

6. UPDATE SAFETY RULES

1. Only controlled published Follow Alongs are listed for updates.
2. Legacy static paths are not listed because they do not have the same shared revision control.
3. The exact programme ID, service identity and service slug are preserved.
4. The package records the published revision used as its starting point.
5. The browser requires the matching owned Shared Draft at that exact revision.
6. A stale package cannot overwrite a newer Shared Draft.
7. The same accepted update package cannot be applied twice.
8. The update creates no release candidate.
9. The update performs no approval or publication.
10. Publishing still uses the existing separate Author and Approver process.


7. IF THE UPDATE IS BLOCKED

Select Shared Drafts and validate again.

If the message says the Shared Draft is a newer revision, do not force the update. Review the newer Shared Draft first, then create a fresh update from the current controlled state.
