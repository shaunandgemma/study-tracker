3. DELETE DRAFT BUTTON

Unpublished drafts with no release-candidate history now have a Delete Draft button.

Deletion requires a second Confirm Delete Draft action.

The database also checks:

1. The user is a signed-in Author.
2. The Author owns the exact draft.
3. The displayed revision is still current.
4. The exact confirmation matches the draft ID.
5. The draft has no release-candidate history.
6. The draft is not live in production.

Only the exact draft and its own revision records are removed. A small metadata-only deletion audit is retained. No draft content is copied into that audit.


4. LIVE DRAFT DISPLAY

The Shared Draft list reads the published candidate IDs and connects each live programme to its exact source draft.

A live draft is:

1. Greyed out.
2. Marked with a green light and Live label.
3. Shown with Deletion disabled.
4. Still available through Continue Draft so a controlled future update can use the original draft.

If production status cannot be verified, Shared Draft deletion fails closed and remains disabled.


5. LAMBDA UPDATE ROUTE

The update route now finds the original draft from the exact published candidate ID. It no longer selects a draft merely because the programme name matches.

For the Lambda update:

1. The published baseline is revision 84.
2. The continuing Shared Draft is revision 87 or newer.
3. The route compares the editable content of the current draft with the immutable published candidate snapshot.
4. A safe rebase is allowed only when that editable content is unchanged.
5. Any real content difference blocks the update.
6. A repeated import with the same handoff fingerprint is blocked as a duplicate.
