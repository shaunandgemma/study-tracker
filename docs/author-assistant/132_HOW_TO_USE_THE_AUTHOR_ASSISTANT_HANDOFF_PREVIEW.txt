HOW TO USE THE AUTHOR ASSISTANT HANDOFF PREVIEW AND CONTROLLED IMPORT

FULL STEP-BY-STEP WALKTHROUGH

1. WHAT THIS WALKTHROUGH COVERS

This walkthrough explains how to open the Author page and safely preview a completed Author Assistant package.

The preview checks the package and its human-acceptance audit.
It does not create a draft, bind an Author, connect to AWS, approve anything or publish anything.

2. PAGES YOU MAY NEED

Author page:
http://127.0.0.1:5173/#author

Approver page:
http://127.0.0.1:5173/#author/approvals

Use only the Author page for this walkthrough.
The Approver page is not needed for the read-only handoff preview.

17. WHAT THE BROWSER CHECKS

The browser checks all of the following before showing the preview:

1. The complete handoff-package fingerprint.
2. The accepted content fingerprint.
3. The accepted-manifest fingerprint.
4. The Step 90A acceptance-audit fingerprint.
5. Each accepted manifest entry.
6. The programme counts calculated from the actual package content.
7. The signed-in Author required for the intended-owner display.
8. The read-only and no-write safety boundaries.

The preview stops if any required value does not match.

18. WHAT STEP 91 DOES NOT DO

Step 91 does not:

1. Bind the signed-in Author identity.
2. Create a Local Draft.
3. Create a Shared Draft.
4. Change an existing draft.
5. Write anything to Supabase.
6. Connect to or change AWS.
7. Create a release candidate or candidate ID.
8. Send anything to the Approver page.
9. Approve or publish a Follow Along.
10. Begin Author Stage 12.

Seeing zero drafts after validation is correct.

19. HOW TO CLEAR THE PREVIEW

1. Choose Clear in the Step 91 preview section.
2. Confirm both selected filenames disappear.
3. Confirm the verified preview details disappear.

Clearing the preview does not delete the saved JSON files.

20. IF AUTHOR ACCESS IS RESTRICTED

Message:
This signed-in account does not have a server-managed Author or Admin role.

Fix:

1. Return to Study Tracker.
2. Choose Sign Out / Switch Account.
3. Sign in with the Author-role account.
4. Open http://127.0.0.1:5173/#author again.

Do not use the Approver account for this page.

21. IF THE PREVIEW ASKS FOR BOTH FILES

Cause:
Only one file was selected, or one selection was cleared.

Fix:

1. Select author-local-handoff-package.json in the first selector.
2. Select author-local-handoff-acceptance-90a.json in the second selector.
3. Run the validation again.

22. IF A FINGERPRINT DOES NOT MATCH

Possible causes:

1. The package and audit came from different service-session folders.
2. One file was edited after acceptance.
3. The wrong JSON file was selected.
4. An older package was paired with a newer audit.

Safe fix:

1. Choose Clear.
2. Return to the correct service-session folder.
3. Select the exact final handoff package and matching acceptance audit from that same folder.
4. Do not edit either file.
5. Validate again.

Do not attempt to manually change a fingerprint.

23. IF A FILE IS REJECTED

The preview rejects invalid JSON, unsupported records and files larger than its safety limit.

Fix:

1. Confirm the file ends in .json.
2. Confirm it is one of the two final accepted files listed above.
3. Confirm it came directly from the Author Assistant session folder.
4. Do not copy text into a newly created replacement file.

24. USING THE PREVIEW FOR A FUTURE AWS SERVICE

The Author Assistant is reusable for other AWS services.

For a future service:

1. Run the Author Assistant for that service.
2. Complete and accept each local stage through the final handoff acceptance.
3. Note the service-session folder printed by the script.
4. Open that folder under:

%LOCALAPPDATA%\StudyTracker\AuthorAssistant

5. Select the final accepted handoff package in the first Step 91 selector.
6. Select its matching human-acceptance audit in the second selector.
7. Make sure both files came from the same folder.
8. Choose Validate Read-Only Preview.
9. Review the service name, counts, Author and fingerprint.

The future service will have a different session folder, programme details and fingerprint.
Never reuse the SQS audit with another service package.

25. IMPORTANT FILE-SAFETY RULES

1. Keep each service package with its matching audit.
2. Do not edit accepted JSON files.
3. Do not email or publicly share private programme content unnecessarily.
4. Do not place OpenAI keys, AWS credentials or Supabase secrets in these files.
5. Keep the Author Assistant session folder until the Follow Along is safely completed.
6. Do not delete any accepted record while a later stage still relies on it.
