EXTERNAL AI - OFFLINE FOLLOW ALONG CREATION STEPS
=================================================

PURPOSE
-------
Create portable Follow Along source files without requiring access to the Study Tracker repository, its builder, validators or fingerprint helper.

The external AI authors the learning content only. The local Study Tracker import command performs conversion, validation, fingerprinting and acceptance later.

1. REQUIRED REFERENCE
---------------------
Read the complete attached file:

STUDY_TRACKER_OFFLINE_FOLLOW_ALONG_AUTHORING_STANDARD.pdf

Treat that document as the governing content and schema contract.

2. REQUIRED OUTPUT
------------------
Return exactly these two complete downloadable files:

1. offline-follow-along-manuscript.json
2. offline-follow-along-preview.md

Do not return a handoff package, session file, acceptance audit, builder or fingerprint.

3. IMPORTANT LOCAL-TOOL BOUNDARY
--------------------------------
You do not need access to:

1. E:\code\study-tracker
2. A local builder
3. Study Tracker validators
4. A fingerprint helper
5. Author or Approver
6. Supabase or AWS accounts

Never stop or refuse because those tools are unavailable.

Never say that the controlled handoff cannot be generated. You are not being asked to generate the controlled handoff. You are being asked to create the two portable offline source files that the local tool will convert afterward.

4. MANUSCRIPT IDENTITY
----------------------
The JSON must use:

1. artifactType: offline-follow-along-manuscript
2. artifactVersion: 1.0
3. One unique programme ID ending in -learning-path
4. One fixed harmless training resource prefix
5. Unique stable phase, task, step, check and cleanup IDs

5. COMPLETE BEGINNER CONTENT
----------------------------
Assume the learner starts with no infrastructure and may not know how to create a folder or file.

For every task include:

1. What the learner will do.
2. Why they are doing it.
3. Every important click, field, value and choice.
4. Complete graphical or Console instructions where relevant.
5. Complete CLI, PowerShell, CloudShell, Terraform or other required route.
6. Every required editable file, JSON policy, YAML document, script or configuration block.
7. Expected visible results.
8. Short verification checks.
9. Relevant official primary documentation sources.

Do not use placeholder, deferred, shortened, future-work or add-later content.

Do not refer to a supplied file or supplied configuration unless its complete content is included in the manuscript.

6. CLEANUP
----------
Include complete manual cleanup in reverse-dependency order.

Cleanup must:

1. Name every exact resource created by the Follow Along.
2. Remove dependent resources before their parents.
3. Include visible verification.
4. Include both graphical and command-line cleanup where those routes were taught.
5. End with a final programme-cleanup acknowledgement.
6. Never perform cleanup automatically.

7. SOURCES
----------
Prefer official primary HTTPS documentation.

Every source ID used by a task must exist in the manuscript source list. Every source should identify the tasks that use it.

8. PREVIEW MATCHING
-------------------
The Markdown preview must:

1. Use the exact programme title as its first H1 heading.
2. Include the exact training resource prefix.
3. Include every task ID from the manuscript.
4. Present the complete phase and task order clearly.
5. Accurately summarise the manuscript without inventing different content.

9. FORBIDDEN CLAIMS AND ACTIONS
-------------------------------
Do not:

1. Claim app validation was completed.
2. Calculate or invent a SHA-256 handoff fingerprint.
3. Create author-local-handoff-package.json.
4. Create author-local-handoff-acceptance-90a.json.
5. Create session.json.
6. Import into Author.
7. Bind an Author identity.
8. Create a candidate.
9. Approve or publish anything.
10. Connect to AWS or Supabase.
11. Modify the Study Tracker repository.

10. FINAL RESPONSE
------------------
Provide the two downloadable files and a short confirmation containing:

1. Programme name.
2. Phase count.
3. Task count.
4. The two exact filenames.

Do not request fingerprint approval. The local offline-import command handles that later.

11. LOCAL STEP PERFORMED BY THE USER LATER
------------------------------------------
After both files are downloaded into the same unique manuscript folder, the user will run:

npm run author-assistant:import-offline -- "<full path to offline-follow-along-manuscript.json>"

That local command—not the external AI—creates and verifies the controlled handoff and fingerprint.
